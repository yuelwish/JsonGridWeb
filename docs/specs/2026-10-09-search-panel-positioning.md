# 搜索面板定位修复：不遮挡滚动条、窄窗口不溢出左栏

## Problem Statement

用户在 JSON 编辑器里按 `Ctrl+F`（或点工具栏「搜索」）打开「编辑器搜索面板」时，悬浮面板的右缘对齐 JSON 编辑器的**外缘**。由于垂直滚动条就住在编辑器外缘，面板一打开就盖住滚动条；窗口较小时，372px 固定宽度的面板还会冲出左侧的 JSON 面板，盖住分隔条与 GRID 面板。

从用户视角看：搜个东西，滚动条被挡、面板还跑到隔壁栏去了。spec 原本就写着「贴内容区右上角定位」，但实现实际贴的是编辑器外缘——代码没对齐 spec 措辞。

## Solution

让「编辑器搜索面板」保持复刻原站 Ace searchbox 的悬浮小框，但把锚点从编辑器外缘改到**内容区右缘**（排除垂直滚动条），并做三重约束：

- 右缘对齐内容区右缘 → 垂直滚动条始终可见可拖；
- `max-width` 上限 = 内容区宽度 → 面板永不溢出 JSON 面板；
- 输入框弹性收缩（单行 flex）→ 窄编辑器下面板整体收缩在内容区内，不换行、不裁按钮。

窗口缩放时面板跟随重新锚定。窄窗口下面板右缘贴内容区右缘；宽窗口下面板仍保持约 371px 的单行自然宽，外观与原站一致。

## User Stories

1. As a JSON 用户, I want 打开搜索面板时不遮挡 JSON 编辑器的垂直滚动条, so that 我可以边搜边滚动、滚动条始终可用
2. As a JSON 用户, I want 窗口较小时搜索面板不溢出左侧 JSON 面板, so that 面板不会盖住分隔条或 GRID 面板
3. As a JSON 用户, I want 搜索面板保持原站 Ace searchbox 的单行外观与约 371px 宽度, so that 视觉与功能对齐原站
4. As a JSON 用户, I want 窄窗口下面板输入框收缩但按钮仍可见可点, so that 小窗口下搜索仍可完整操作
5. As a JSON 用户, I want 窗口缩放后面板跟随编辑器重新定位, so that 面板不会停留在旧位置
6. As a JSON 用户, I want Ctrl+F 与工具栏「搜索」按钮打开的面板长得一样, so that 我不需要记住两套 UI
7. As a JSON 用户, I want 面板内的查找/替换/计数/无匹配红框等既有功能不受影响, so that 修复定位不会破坏已有交互
8. As a macOS 用户, I want Cmd+F 也走同一套定位逻辑, so that 行为跨平台一致
9. As a 维护者, I want 面板定位同步执行、不依赖 requestAnimationFrame, so that 不出现「先贴底部再弹到右上角」的闪烁
10. As a 维护者, I want 定位逻辑抽成可复用函数并挂到窗口缩放事件, so that 打开瞬间与缩放后走同一段代码
11. As a 维护者, I want 定位逻辑有源码层回归断言, so that 后续改动不会让面板重新盖住滚动条或溢出左栏
12. As a 维护者, I want 面板关闭时清理 resize 监听, so that 不产生监听器泄漏
13. As a 维护者, I want 这次改动不新增运行时依赖、不触碰 worker 序列化, so that 产物体积与 npm run verify 均不受影响

## Implementation Decisions

- 定位逻辑抽成模块级函数，面板定制完成后**同步**调用一次，并注册为 `window resize` 监听器；面板关闭时在既有面板清理分支里移除监听器。
- 右缘基准取编辑器内滚动容器的**可见内容右缘**（`getBoundingClientRect().left + clientWidth`），`clientWidth` 已排除垂直滚动条；无滚动条时退化为编辑器右缘。
- 面板 `max-width` 设为内容区宽度，`left` 钳制在编辑器左缘与「内容区右缘 − 面板宽」之间。
- 必须先让面板容器收缩到 `max-content` 再量面板宽度；若先量宽，量到的是编辑器全宽，`left` 会被钳到最左，表现为「面板左对齐、脱离右缘」（实现过程中踩过并已修复的坑）。
- 面板表单行改为单行 flex（不换行）：输入框保持 `17em` 自然宽但允许收缩（`flex: 0 1 auto; min-width: 0`），按钮固定原宽（不收缩）。这样宽窗口下自然宽约 371px，窄窗口下输入框先收缩、按钮不被挤到第二行。
- 保持面板外观、DOM 结构、搜索/替换/计数逻辑不变；本次只改定位与表单行的布局方式。

## Testing Decisions

好的测试只验外部可观察行为。本仓库无浏览器测试框架，唯一先例是 `npm run verify:search`（源码层代理断言，可防止绑定被误删或绕过）。本次沿用该先例，在同一个脚本里为定位逻辑增加代理断言：

- 存在模块级定位函数；
- 定位基准读取滚动容器的 `clientWidth`（代理「锚定内容区而非编辑器外缘」）；
- 设置 `max-width` 上限（代理「窄窗口不溢出左栏」）；
- `left` 不低于编辑器左缘（代理「不向左侧溢出」）；
- 注册并在面板关闭时移除 `resize` 监听。

这些断言只能证明源码关系存在，无法证明浏览器行为；浏览器行为靠人工验收清单证伪：

1. `npm run build`，在 `dist` 上起服务，打开页面，加载样例数据。
2. 在宽窗口（如 1200px）按 `Ctrl+F`：面板右缘应贴在内容区右缘（滚动条左侧），滚动条可见可拖；面板保持单行约 371px。
3. 把窗口缩到 845px：面板收缩在内容区内，右缘仍贴内容区右缘，不溢出到分隔条/GRID。
4. 缩到 600px：面板进一步收缩，仍完全位于 JSON 面板内，按钮可见可点。
5. 面板打开时缩放窗口：面板跟随重新锚定，不留在旧位置。
6. 输入存在的串：计数更新、高亮出现、Enter/Shift+Enter 可跳转；点 `+` 展开替换行；Esc 关闭后面板 DOM 清理、再按 `Ctrl+F` 正常重开。
7. 切暗色主题重复第 2 步：面板配色正确。

回归护栏：`npm run verify`（紧凑序列化逐字节回归，869 用例）必须全绿；`npm run build`（含 tsc）必须通过；gzip 体积保持 < 180 kB 红线。

## Out of Scope

- GRID 搜索面板的定位与快捷键。
- 面板 DOM 结构、配色、间距等视觉微调。
- 切换 JSON/GRID 全屏时面板实时跟随（定位为 fixed，全屏切换不触发 resize 事件；该行为在本次改动前已存在，属既有限制）。
- 拖动分隔条时面板实时跟随（需要 ResizeObserver，项目零 polyfill 约束下禁用）。
- 引入浏览器驱动测试框架。

## Further Notes

- 修复前实测：600px 视口下 JSON 面板宽 200px，面板 0..372px 溢出 172px，盖住分隔条与 GRID；修复后面板 0..185px，完全在内容区内。1200px 视口下内容区右缘 385px（滚动条占 385..400），面板右缘对齐 385px，滚动条可见。
- 本次实现让代码真正对齐了原 spec 验收清单里「贴内容区右上角定位」的措辞。
